## Implementation and architecture

The [approved gate](../design-gates/NodalOpenVafValidation-DG-v0.1.md) keeps external
compiler integration in `core.integrations`. Its shared `ToolProcessRunner` replaces
the bridge's duplicated execution machinery. The bridge retains protocol,
staging, normalization and diagnostic ownership. The production adapter owns
pinned version/hash checks, fixed arguments/environment, fresh attempts, raw logs,
request identities and finite ELF-output validation. It has no bridge dependency,
compilation cache, model transformation or hierarchy flattening.

The existing backend catalog owns separate generated consumer pins/observations;
all F-047 language features and native operation tables remain unchanged. Consumer
success, source-map validity and Nodal language eligibility are separate facts.
The selected successful baseline is Linux x86-64 OpenVAF-reloaded
`20260616-3-g0e83f1ed`, executable SHA-256
`b117284d8f871dbf54609ab009cdff819f443d8d33064111b8b0782af5c7e931`.
Its fixed arguments are `--target x86_64-unknown-linux --target_cpu generic
--interface OSDI -O 3`, with separate model and output argv elements.

Native Support owns the validated authored source inventory, indexed once per root.
Backend markers use exact operation identity for parameters, named instances and
contributions. The private default-false bridge option requests these markers.
Default bytes remain unchanged. Missing contribution spans stay target-only;
no ancestor, target-name or temporary-MLIR fallback is invented. The adapter binds
mapping to exact model bytes and associates only the immediately annotated physical
statement. Native provenance, runner and adapter reviews found no blocking defect.

## Scale, determinism and finite limits

The complete repeated hierarchy retains four named instances and two reusable
module definitions; the nested hierarchy retains three definition levels and all
three canonical instance statements for five captured source occurrences. Rejection
by a consumer remains a blocked result; leaves are never extracted to manufacture
success. Parameter actuals remain symbolic or literal as authored.

Capture is bounded to 8 MiB combined stdout/stderr; the CLI input read is bounded
to 16 MiB. Linux compiler runs require acknowledged process-group containment.
Unacknowledged startup expires after 20 ten-millisecond intervals; failure cleanup
has a bounded 250 ms grace period. Other-platform bridge descendant observation
and deliberate session-escape limits are explicit in the gate. Wrapped exec
126/127 failures are ordinary exits, not guessed launch failures from stderr.

No compile-result reuse is introduced. Request identity covers exact model bytes,
logical name, tool/version/hash, catalog/profile, ordered arguments, controlled
environment, timeouts, mapping and source provenance. Fresh directory names do not
change semantic identity. Model/log scans and tool hashing are proportional to
retained bytes; source-map lookup is indexed. There is no whole-pipeline speedup or
unbounded-scale claim. Avoiding a cache is justified until a real reuse workload
requires its invalidation complexity.
