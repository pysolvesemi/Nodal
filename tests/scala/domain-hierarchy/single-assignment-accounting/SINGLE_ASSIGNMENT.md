# Bounded one-assignment accounting

This is scoped accounting groundwork, not default-capacity admission or completion
of Foundation 58. The unchanged 65,536-unit driven positive still fails. The fixed
131,072 policy remains explicitly diagnostic; no limit or callback authority is
increased and no semantic validator is skipped.

## Owner and architecture

ConstructionSession extends its existing bound-domain profile for exactly one
canonical root InstanceInput assignment from the finalized registered singleton.
It proves the actual declaration, child-port binding, source/request identity,
literal descriptor, domain, source ordinal and complete ordinal inventory. The
unchanged zero-assignment branch and domain-free accounting remain separate.
Unknown shapes select coarse accounting before admission. A changed proof after
admission poisons the owner instead of falling back, refunding or retrying.

Existing preparation, naming, driver validation and export paths still run.
Additional probes charge newly live direct-target, driver-map, assignment-record,
operand-path and source-export work at their existing owners. No parallel graph,
registry or semantic engine is introduced. Public callbacks, generalized contexts,
register/observation topology and additional assignments remain outside this
profile. Independent local graph/type limits are unchanged.

The maintained Scala witness executes the actual public assignment:

    def driveCompletedScalar(proxy: Signal[SInt]): Unit =
      proxy := result.asInstanceOf[Expr[SInt]]

The current increment does not affect generated Verilog-*.
It changes accounting eligibility and charges, not hardware construction or
lowering. Complete baseline/candidate snapshots are byte-identical; no new
Verilog-generation or downstream-consumer claim is made.

## Focused evidence

The maintained runner freshly compiles nine groups and executes 25 selected suites
with Scala 3.8.4, JDK 25, -Wunused:all and -Werror. This includes the driven 17 cases
plus calibration, seven raw corruption probes, twelve additional structural
exclusions and post-admission poisoning, exporter exhaustion/recovery, broader
exporter parity, and matched predecessor comparisons. All suites pass.

Corruption cases are labeled test seams, not organically authored unsupported
programs. Post-admission ordinal mismatch requires the exact assignment-identity
failure, advances the epoch, invalidates a held query, preserves registries and
serials, refuses further publication/drain and recovers only in a fresh Session.
The assignment-record exporter costs 56 units; the identical next invocation
with 55 units fails in the newly live RHS expressionPath callback. All accounting
flags restore. This is exporter-seam exhaustion, not a fabricated full publication
or proof of partially mutated exporter registries.

Six same-capture exporter comparisons cover complete module/control vectors,
shape indices, reachable expressions, assignment records and source indexes.
Complete ConstructionSnapshot text from the same compiled fixture and identical
lookup is equal on both APIs: 11,653 bytes, SHA256
`a24652aacbf7e478e049544a1588568ad3c6cda74c8064ab105c8b255aa2bdc4`.
That comparison includes the final inline source-map assembly. The baseline uses
the candidate source projection only for this explicitly named parity diagnostic.

Matched full-finish costs are 123,636 baseline and 88,366 candidate units. This is
a measured accounting reduction, not a CPU or universal performance claim.
The main driven diagnostic costs 88,433; source locations and observation routes
have real costs, so distinct harness totals are not interchangeable. Six C2a
controls have identical baseline/candidate logs and observed fees. An additional
organic domain-free witness contains three actual assignments and finishes with
13,641 units remaining on both APIs. Automatic precompleted activation uses 34,978
units on both; this does not demonstrate automatic pending-cell completion.

Sixteen retained predecessor groups pass, including the already accepted
exact-arity helper, and all fourteen retained raw files remain byte-identical.
Those retained consumers were not freshly compiled. The default driven positive
is deliberately excluded from passing admission suites: its separate unchanged
run fails at the assignment descriptor proof with five units remaining.

## Reproduction and source identity

The manifest pins the candidate and baseline APIs, maintained fixture bytes and
original virtual source paths. Supply each group an immutable source projection
containing the exact 97 effective source files, its fixtures, a regular build.mill
file and core/scala and docs directories. Markers and all input bytes are checked
and pinned before and after execution. A markerless projection is invalid:
SemanticOrigin otherwise falls back to the real repository. Earlier scratch
runs with that defect remain preserved but are not projected-source evidence;
correctly anchored reruns establish the results above.

Run python3 -I -B run_single_assignment.py --help for explicit input arguments.
Provide --repository-root, --java, --compiler-classpath, --runtime-classpath,
--api-jar, --baseline-api-jar, repeated --bridge-jar, --effective-source-map,
--output-root and --timeout. Each selected group also requires its
--GROUP-source-root and --GROUP-source-pins JSON. The runner never rebuilds an API
or repairs a lookup. Outputs must be new and ignored. Whole-output and predecessor
log comparisons fail closed when both corresponding suites are selected.

To reproduce the still-failing default positive, run the freshly compiled driven
main with argument default instead of diagnostic, with the same pinned classpath
and NODAL_WORKSPACE. Do not relabel this as accepted default behavior.

Independent architecture/test review is scoped to this profile. No CI, exhaustive
qualification, publication retry or held CIRCT/firtool action was performed.
