## Portable target and internal storage contract

Keep the required backend at IEEE 1364-2005. Permit internal fixed-size,
multidimensional unpacked arrays of packed net or variable elements, subject to
explicit target/tool capabilities. An internal unpacked array is not an
unpacked-array module port and does not require a SystemVerilog backend.
AMD's [Verilog-2001 support documentation](https://docs.amd.com/r/2022.2-English/ug901-vivado-synthesis/Verilog-2001-Support)
identifies multidimensional arrays and arrays of nets; that vendor reference
is not qualification of every rank, access pattern or tool in Nodal's matrix.

These are required publication examples, not output generated by this update:

```verilog
// Packed internal alternatives: ten elements, then a rank-two shape.
wire [8*10-1:0] v;
wire [WIDTH*ROWS*COLS-1:0] matrix;

// Unpacked internal alternatives with the same logical element order.
wire [8-1:0] v_elements [0:10-1];
wire [WIDTH-1:0] matrix_elements [0:ROWS-1][0:COLS-1];
reg  [WIDTH-1:0] matrix_state [0:ROWS-1][0:COLS-1];
```

Select `wire` versus `reg` from driver/assignment semantics, not from the layout
option; a `reg` declaration alone is not a request for clocked storage. Preserve
combinational coverage, reset/update behavior, domain ownership and driver rules.
`Vec` stays structural and `Mem` keeps its explicit addressable-storage/effect
contract. Dynamic indexing or unpacked syntax cannot silently introduce RAM,
latency, collision policy or a resource-mapping transformation.

Do not emit SystemVerilog multidimensional packed declarations, unpacked-array
ports, `logic`, whole-unpacked-array assignments or assignment patterns to
implement this portable profile. Lower aggregate copies, initialization and
updates into legal element-wise operations with unchanged semantics. Record
supported rank/access combinations per pinned tool; reject unsupported explicit
requests rather than silently changing the selected layout. Do not impose a
vendor-specific rank limit on the target-neutral shape model.

Analog terminals, branches, continuous quantities and discrete real nets are
not serialized into these digital carriers. Resolved digital `inout` remains
under its existing typed connectivity/capability contract: input/output packing
assignments are not a substitute for bidirectional net identity, and opposing
continuous assignments must not manufacture a bidirectional bridge.

## Flat ports and recursive field-vector compatibility

Internal layout does not select or modify the port ABI. A scalar-element Vec
port uses one one-dimensional packed carrier, including concrete shapes:

```verilog
input  wire [8*10-1:0] v;
output wire [8*4*10-1:0] matrix;
input  wire [WIDTH*DEPTH-1:0] samples;
```

Retain the explicitly selected recursive named-field-vector ABI for Vecs of
directionless Struct/Bundle values. That ABI emits one packed carrier per scalar
leaf, not one mandatory whole-record carrier and not numbered element ports:

```verilog
input wire [WIDTH*COUNT-1:0] pixels_red;
input wire [WIDTH*COUNT-1:0] pixels_green;
input wire [WIDTH*COUNT-1:0] pixels_blue;
input wire [COMP_WIDTH*COUNT*SAMPLES-1:0] pixels_samples_red;
```

Keep unchanged aggregate-valued source. Walk each full leaf path with its own
width and ordered enclosing Vec dimensions; dimensions belonging only to a
sibling field must not enter that leaf's product. Apply internal layouts and
bridges per leaf where appropriate. Preserve resolved Interface roles/directions,
field names, enum encodings, source paths and parent/child parameter bindings.
Do not make logical flattening/serialization field-major merely because the
physical ports are field-wise. Existing external/black-box ABIs change only
through an explicit compatible profile or a recorded, verified adapter.

## Emission options and precedence

The following names/defaults are the requested configuration candidates. They
are not advertised as existing compiled APIs. F-065.A.4.1 must freeze their exact
additive spelling, application scope and compatibility before protected API work.
Reuse existing layout/materialization models, not a second semantic engine.

| Option | Default | Required effect |
| --- | --- | --- |
| `preserveConstantVecs` | `false` | When true, preserve eligible concrete internal Vec aggregates instead of splitting them into independent element declarations. |
| `preserveConstantLoops` | `false` | When true, preserve supported concrete-bound `hdlRange` iteration in legal generated HDL loops instead of unrolling it. |
| `vecLayout` | `PackedVector` | Select a flat packed vector or an unpacked array of packed elements for materialized internal Vec aggregates. |

`PackedVector` maps to the existing `Layout.FlatPacked` meaning; the internal
`Unpacked` choice maps to `Layout.Unpacked`. Do not introduce another layout
algebra or enable `Layout.PackedDimensions` for portable Verilog. Boundary
layout policies remain separate and authoritative.

The precedence is semantic legality, explicit boundary ABI, required
materialization, constant-aggregate preservation, then the selected internal
aggregate layout. With `preserveConstantVecs=false`, verified scalarization is
permitted, not mandatory; `vecLayout` applies to aggregates that remain. Neither
setting discards semantic rank/dimensions, width/signedness or parameter
provenance. Preservation does not force dead values to survive or unnecessary
single-use expression wires to be materialized.

Symbolic dimensions and target-visible symbolic iteration remain symbolic with
all settings: no default-value substitution, per-value module cloning or loss
of a legal parameter override. A requested preservation/layout that cannot be
honored within the qualified profile receives a specific diagnostic; do not
silently ignore the setting or claim preservation while scalarizing/unrolling.
The configuration gate must distinguish permitted dead-code removal from an
unhonored preservation request. Record selected options, effective decisions,
capability limits and algorithm versions in manifests and build/cache keys.

## Unified hdlRange and loop preservation

Keep the current unified user-facing iteration direction:

```scala
for i <- 0 until 10 do
  // Ordinary Scala elaboration; this option does not reconstruct a source loop.

for i <- hdlRange(0, 10) do
  // Target-visible concrete iteration, eligible for constant-loop preservation.

for i <- hdlRange(0, count) do
  // Target-visible iteration with a legal symbolic integer bound.
```

Nodal determines legal target regions from captured typed effects, ownership,
dependencies and declared clock/reset domains. One `hdlRange` may produce
structural generate loops, combinational assignments/regions, procedural loops
for state updates, or a combination. Do not require new separate `genRange`
or `hwRange` APIs, a user-selected backend loop kind or a new `clocked:` wrapper.
Existing explicitly exposed compatibility forms retain their own contracts.

`preserveConstantLoops` controls preservation versus verified unrolling, not
staging or process ownership. False is permission for a legal transformation,
not permission to change instance/state multiplicity, ordering, source identity,
latency or symbolic parameterization. True does not promise exactly one target
loop: partition incompatible clock/reset/process groups and retain legal scope.
Fuse compatible loops only with proof; preserve guard/update priority and
loop-carried dependencies. Do not create runtime hierarchical instance selectors
or duplicate instances/state across partitions. Use legal typed per-lane views
or processes inside generate scopes, or reject an illegal partition.

Retain existing half-open bounds, finite envelopes, static step and overflow
checks, with enforced `maximum` only when no finite bound is otherwise available.
Empty/singleton iteration has its defined behavior; an empty loop is not blanket
permission for a zero-sized Vec. Reject dynamic/unbounded trip counts and hidden
multi-cycle/FSM behavior. No inference or reconstruction of ordinary Scala
repetition is introduced by either preservation flag.

## Factorized publication and canonical bridges

Maintain both the semantic width/shape expression and its evaluated/proven
properties. Preserve element width and ordered dimensions through construction,
authoritative MLIR, hierarchy, optimization and structured target emission:

```verilog
wire [8*10-1:0] constant_vec;
wire [WIDTH*DEPTH-1:0] parameterized_vec;
wire [8-1:0] constant_elements [0:10-1];
```

For preserved aggregates, keep meaningful factors and dimension ranges rather
than publishing only `[79:0]`, `[7:0]` and `[0:9]`. This is part of aggregate
publication, not a fourth public switch. Whitespace and redundant parentheses
need not be frozen. Retain typed expression provenance, not strings recovered
from generated HDL or guessed factorization of an evaluated total such as 80.

Internal validation may normalize/evaluate expressions for positivity, shape
comparison, index bounds and total-width checks without replacing the publication
form. Check both compiler arithmetic and target constant-expression sizing and
overflow over legal parameter ranges. Use a semantics-preserving, width-safe
factorized form where needed, or diagnose the unsupported envelope; readable
spelling never takes precedence over correct HDL arithmetic.

Use the existing zero-origin, row-major mapping: the rightmost dimension is
contiguous and logical element zero occupies the low element slice. For rank two:

```text
offset(row, col) = ((row * COLS) + col) * WIDTH
```

The following illustrative input-unpack/output-pack bridge uses that mapping;
it is not an executed or generated acceptance artifact:

```verilog
module MatrixBridge #(
  parameter integer WIDTH = 8,
  parameter integer ROWS = 4,
  parameter integer COLS = 10
)(
  input  wire [WIDTH*ROWS*COLS-1:0] matrix_in,
  output wire [WIDTH*ROWS*COLS-1:0] matrix_out
);
  wire [WIDTH-1:0] elements [0:ROWS-1][0:COLS-1];
  genvar row, col;
  generate
    for (row = 0; row < ROWS; row = row + 1) begin : rows
      for (col = 0; col < COLS; col = col + 1) begin : columns
        assign elements[row][col] =
          matrix_in[((row*COLS + col)*WIDTH) +: WIDTH];
        assign matrix_out[((row*COLS + col)*WIDTH) +: WIDTH] =
          elements[row][col];
      end
    end
  endgenerate
endmodule
```

Generalize the stride formula to arbitrary supported rank and nested leaf paths.
Bridges add no state or latency and preserve direction, driver ownership and
partial/full updates. A `Vec[SInt]` flat carrier stays signless; signed elements
use correctly signed internal declarations/views. Verify sign extension,
comparisons and shifts after part selection instead of treating the full carrier
as one signed number. Preserve four-state behavior within each declared tool
profile; a two-state proof does not establish four-state simulation behavior.
