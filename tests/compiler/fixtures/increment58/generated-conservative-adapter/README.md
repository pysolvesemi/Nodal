# Generated conservative adapter regressions

Source-only preservation of the accepted 125-execution adapter selection.
This is a focused regression harness, not exhaustive qualification. It neither
builds nor installs tools, discovers historical binaries, imports acceptance
receipts, runs firtool, nor changes a repository or publication state.

## Run

Use Python 3 and a compatible prebuilt probe:

From the repository root:

    PYTHONDONTWRITEBYTECODE=1 python tests/compiler/fixtures/increment58/generated-conservative-adapter/increment58_conservative_adapter_runner.py --probe /absolute/path/to/probe --public-input-dir /path/to/coherent-source53/outputs --output-dir .work/adapter-run
    PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests/compiler -p test_increment58_generated_conservative_adapter.py

The top-level test entry loads the uniquely named runner by its absolute file
location. The runner loads its uniquely named sibling generator the same way;
neither depends on a generic `run` or `generators` module or sys.path insertion.
Control-test temporary inputs live only in the repository-root ignored `.work/`
and are removed by TemporaryDirectory, including on test failure. The test
finds that root using the enclosing AGENTS.md and CONTRIBUTING.md markers.

The output directory must not exist. Generated inputs/results stay there.
At least 237 MiB free plus the indicated temporary allowance is required.
Each probe invocation has a fixed 60-second timeout. A timeout propagates as
a failed run, never an accepted result or a successful summary. Two budget
inputs are generated one at a time and removed even on assertion failure or
probe timeout. There is no native build target yet. The preserved probe source is
byte-identical to the accepted source; compiling it against a fresh build is a
separate integration task and is not claimed by this preservation check.

## Ownership and source provenance

`increment58_conservative_adapter_generators.py` contains deterministic mutations of named source templates.
There are no compressed snapshots, opaque patches or generated budget files.
`cases.json` is a maintained expectation table: each named input, its digest,
mode, expected status and output digest. It contains no timing, actual results,
absolute paths or old binary references. Every one of the 125 checks runs,
including repeated checks of one input in different groups.

`generated_conservative_adapter_probe.cpp` preserves the accepted
child-summary probe exactly. Its exercised modes are verify, adapt, emit,
transaction and child-pairs. The runner also retains the ten selected-child
structural checks: real children/ports/arrays, correspondence targets,
discipline/access/orientation, loop bounds and authored-operation invariance
for counts 1/3/1000. Refusal cases retain empty-output hashes, diagnostic checks
where originally required, and transactional no-mutation semantics.

The templates are test inputs, NOT a claim that every MLIR file was authored
by hand. `legacy/*.roundtrip.mlir` preserve historical adapter-rendered forms.
`scala-predecessor/first/outputs/{local,child}.mlir` were generated by
`scala-provenance/first/src/{Source,Replay}.scala`;
`scala-predecessor/controls/outputs/{nested-member,count0,count1}.mlir` were
generated by those definitions and
`scala-provenance/controls/src/{SourceControls,ReplayControls}.scala`.
The Scala replay uses ConstructionKernel.inspect and ScalaToMlirBridge for
Verilog-A. The Scala files are preserved as provenance, not executed by this
native-only harness. Their filenames/line positions affect emitted source
locations; do not rename them and claim unchanged historical byte hashes.

Other templates preserve reviewed native mutations or source-derived forms
whose complete original generator was not available. Their literal source is
the authoritative regression input. `selected-child/parameter-bound.mlir`
retains the accepted range bounds, parameter_constraint and parameter_envelope;
the stale historical extras recipe omitted these and is deliberately not used.
`legacy/child.mlir` retains accepted root-module/binding attributes absent from
its old mutation script. No stale recipe is presented as reproducible.

The public-five are NOT copied here. `--public-profile coherent-source53` is
the default. Supply the coherent source53 replay output root containing
`selected-first/selected-child.mlir` and
`selected-controls/{nonunit,unused-leaf,boundary-only,two-views}.mlir`.
These expectations originate from a fresh replay of fixture commit
`e3da389dddcdaccef7f343335d3a279114cf843f` against the accepted source53
API/bridge/plugin. `public-profiles.json` pins exact complete MLIR and complete
Verilog-A hashes for both profiles; correspondence and provenance comments are
never normalized or removed.

For the previous mixed-root outputs, pass `--public-profile historical` and
a directory with the five files directly inside. Historical expectations are
preserved exactly. Selecting the wrong profile fails the input digest check;
unknown profiles are rejected. There is no auto-detection or fallback.

Coherent replay changes source locations and source-induction identity in
MLIR and emitted provenance comments. This is a deliberately separate coherent
source-provenance profile, NOT historical byte parity. The native predecessor
cases and all duplicate/budget controls retain their original expectations.
The five public inputs retain their separately maintained Scala source owner.

## Maintenance boundaries

Use readable semantic mutations with asserted anchors and final input hashes.
Do not replace a failed expectation merely to make an implementation pass.
Keep accepted historical bytes distinct from deliberate new source-generation
behavior. A changed compiler may require a reviewed expectation update, not
reconstruction of an old binary or ignored source tree.

Maintained source lives under
`tests/compiler/fixtures/increment58/generated-conservative-adapter/`, with the
control-test entry at
`tests/compiler/test_increment58_generated_conservative_adapter.py`.
An eventual native probe target needs explicit repository build integration
review; none is guessed here.
